# shuffle_psv

`shuffle_psv` は、PSV ファイル内のレコードをランダムにシャッフルするツールです。

- 入力: PackedSfenValue 40 バイト固定長ファイル
- 出力: 同一レコード群をランダム順に並べ替えたファイル
- 特徴: シード指定で再現可能、大規模ファイル対応のチャンク方式と opt-in の段階削除あり

NNUE 学習では教師データの並び順がバッチ勾配に影響するため、十分なシャッフルが重要です。

## シャッフル方式

### インメモリ方式（デフォルト）

全レコードをメモリに読み込み、Fisher-Yates アルゴリズムで完全シャッフルします。

- メモリ使用量 = ファイルサイズ
- 最も高品質なシャッフル
- メモリに収まるファイルサイズでのみ使用可能

### チャンク方式（`0 < --chunk-size < 入力レコード数` の場合）

メモリに載りきらない大規模ファイル用。2 パスで処理します。
`--chunk-size` が `0`、または入力レコード数以上の場合はインメモリ方式になります。

**Pass 1**: 各レコードをランダムに選んだチャンクファイルに振り分け

- レコードの所属チャンクがランダムに決まるため、チャンク間のシャッフルが実現される
- `--delete-input-after-pass1` 指定時は、全レコードの振り分けと全チャンク writer の flush が成功した後に入力を削除する。Pass 1 が完了しなければ入力は削除しない

**Pass 2**: 各チャンクをメモリに読み込み、チャンク内を Fisher-Yates でシャッフルし、出力ファイルに書き出し

- 複数チャンクをバッチ並列で処理（Pass 1 後のチャンク実ファイルサイズとチャンクごとの読み込みバッファを使い、Linux / Windows / macOS で取得した利用可能メモリの 70% を上限に自動編成）
- Linux コンテナではホストの利用可能メモリと cgroup の残量のうち小さい方を使用する
- 処理開始前の検査では、Pass 1 の入力バッファと全チャンクの書き込みバッファもピークメモリに含める
- Pass 1 後に最大チャンクの実サイズと読み込みバッファを再検査し、利用可能メモリの 80% を超える場合は `--force` なしでは停止する
- 単一チャンクだけで 70% の予算を超える場合は警告し、そのチャンクだけをロードする
- 利用可能メモリを取得できない場合は安全のため停止する。`--force` 指定時も Pass 2 のバッチサイズは 1 に制限される
- 一時ファイルは `TMPDIR` 環境変数で指定したディレクトリに作成される
- `--delete-chunk-files` 指定時は、各チャンクを出力へ書き出して flush した直後にそのチャンクを削除する。削除失敗は警告して処理を続ける

結果として、チャンク間・チャンク内ともにランダムな完全シャッフルになります。

## チャンクサイズの選び方

`--chunk-size` はチャンクあたりの **レコード数** で指定します。

メモリ使用量の目安: `chunk_size × 40 bytes`

| chunk_size | メモリ使用量/チャンク |
|---|---|
| 500,000,000 (5億) | 約 18.6 GiB |
| 1,000,000,000 (10億) | 約 37.3 GiB |
| 2,000,000,000 (20億) | 約 74.5 GiB |

Pass 2 では複数チャンクを並列ロードするため、実際のピークメモリは上記の倍数になります。バッチは Pass 1 後の各チャンクの実ファイルサイズ、チャンクごとの 8 MiB 読み込みバッファ、利用可能メモリに基づいて自動編成されます。

チャンク数は最大 1,000 に制限されています。チャンクが多すぎる場合は `--chunk-size` を増やしてください。

## 一時ファイルのディスク使用

チャンク方式では、Pass 1 で入力ファイルと同じサイズの一時ファイルが作成されます。

- デフォルトの一時ディレクトリは `/tmp`（システムの `TMPDIR` に従う）
- 大規模ファイルの場合、`/tmp` の空き容量が不足する可能性がある
- `TMPDIR` 環境変数で十分な空き容量のあるディレクトリを指定すること

```bash
# 例: 一時ファイルを /path/to/fast-tmp に作成
TMPDIR=/path/to/fast-tmp shuffle_psv --input large.psv --output shuffled.psv --chunk-size 1000000000
```

## 使用例

### 基本: 小規模ファイルのシャッフル

```bash
cargo run --release --bin shuffle_psv -- \
  --input data.psv --output shuffled.psv
```

### シード指定（再現性のため）

```bash
cargo run --release --bin shuffle_psv -- \
  --input data.psv --output shuffled.psv --seed 42
```

### 大規模ファイル: チャンク方式

```bash
TMPDIR=/path/to/fast-tmp cargo run --release --bin shuffle_psv -- \
  --input large.psv --output shuffled.psv \
  --chunk-size 1000000000 --seed 42
```

### 大規模ファイル: 段階削除でピークディスク使用量を抑える

```bash
TMPDIR=/path/to/fast-tmp cargo run --release --bin shuffle_psv -- \
  --input large.psv --output shuffled.psv \
  --chunk-size 1000000000 --seed 42 \
  --delete-chunk-files --delete-input-after-pass1
```

`--delete-input-after-pass1` は入力を削除する破壊的オプションです。入力を残したい場合は `--delete-chunk-files` だけを指定してください。どちらのフラグも `0 < --chunk-size < 入力レコード数` で選ばれるチャンク方式でのみ有効です。インメモリ方式へフォールバックした場合は入力も削除しません。shuffle の結果や seed 消費は変わりません。

## オプション一覧

| オプション | 説明 | デフォルト |
|---|---|---|
| `--input`, `-i` | 入力 PSV ファイルパス | — |
| `--output`, `-o` | 出力 PSV ファイルパス | — |
| `--seed` | 乱数シード（再現性のため） | ランダム |
| `--chunk-size` | チャンクサイズ（レコード数）。0 または入力レコード数以上 = インメモリ方式 | `0` |
| `--force` | メモリ不足警告を無視して強制続行 | off |
| `--delete-chunk-files` | Pass 2 で出力済みのチャンクを順次削除（チャンク方式のみ） | off |
| `--delete-input-after-pass1` | Pass 1 完全成功後に入力を削除（チャンク方式のみ） | off |

## ディスク容量

チャンク方式のピークディスク使用量は、段階削除フラグによって変わります。以下の倍率は入力・一時ファイル・出力を合算した目安です。

| 指定 | ピーク | 入力の扱い | チャンクの扱い |
|---|---:|---|---|
| なし（デフォルト） | 約 3 倍 | 保持 | 正常終了時まで保持 |
| `--delete-chunk-files` | 約 2 倍 + 最大 1 チャンク | 保持 | 出力済みから順次削除 |
| `--delete-input-after-pass1` | 約 2 倍 | Pass 1 後に削除 | 正常終了時まで保持 |
| 両方 | 約 2 倍 | Pass 1 後に削除 | 出力済みから順次削除 |

ピークを入力サイズの約 2 倍に確実に抑えるには、`--delete-input-after-pass1` を指定します。`--delete-chunk-files` 単独では、現在のチャンクを出力へ flush してから削除する短い区間に、そのチャンクが一時ファイルと出力の両方へ存在します。

通常は一時ファイルを正常終了時に自動削除します。`--delete-input-after-pass1` 指定時は、入力を削除する直前に一時領域を永続化し、出力の flush が完了した後で明示的に削除します。入力削除後に Pass 2 のエラーまたは Ctrl-C が発生した場合はエラー終了し、stderr に表示したパスへチャンクを残します。`--delete-chunk-files` を併用していなければ、残ったチャンクを `cat` で連結して全レコードを復元できます。併用時は、途中出力と未処理のチャンクを連結してください（いずれも順序は元入力と異なります）。

OOM kill や SIGKILL で強制終了した場合も一時領域が `TMPDIR` に残ることがあります。手動で確認・削除してください。

`--delete-chunk-files` で個別チャンクの削除に失敗した場合は stderr に警告を出し、shuffle 自体は続行します。`--delete-input-after-pass1` で入力の削除に失敗した場合はエラー終了し、永続化済みのチャンクを残します。

`TMPDIR` は入出力ファイルと同じ高速ディスク（SSD）上に置くことを推奨します。

## 注意

- デフォルトでは入力ファイルを変更しません。`--delete-input-after-pass1` 指定時だけ、Pass 1 完全成功後に削除します
- 出力ファイルのレコード数は入力と同一です（増減なし）
- Ctrl-C で中断可能（出力は不完全になります）。入力削除後の中断はチャンクを保全してエラー終了します
- 処理開始前にクロスプラットフォームのメモリ充足チェックが行われます。不足時または取得不能時はエラーで停止し、`--force` で強制続行できます
