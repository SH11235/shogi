# book_from_csa

CSA 棋譜群(floodgate など)から YANEURAOU-DB2016 テキスト `.db` 定跡を生成するツール。

生成した `.db` は `rshogi-book` のリーダ(`Book::from_path`)でそのまま読め、エンジンの
定跡 probe に使える。

設計の要点 (常に新規スタンドアロン `.db` 出力・消費時間による定跡手判定・
決定性の担保) は `book_from_csa.rs` 冒頭の doc comment を参照。

## 使い方

```bash
cargo run --release -p tools --bin book_from_csa -- \
    --root /path/to/csa \
    --min-rating 4000 \
    --out book.db
```

`--root` 配下を再帰的に走査して `*.csa` をストリーミング処理し、
序盤の指し手を集計して `--out` に `.db` を書き出す。

## 設計方針

- **出力は常に新規スタンドアロン `.db`**。既存 book への追記・マージはしない。
  「どの手を book に入れるか」は生成時フラグで制御し、既存 book との統合は別工程として
  明示的に行う(盲目的追記の構造的排除)。
- **定跡手の判定は消費時間で行う**(既定オン)。各手番側の初手から連続して消費時間が
  閾値以下(即指し)である間を、その側が実際に定跡として指している区間とみなして集計する。
  単純な「先頭 N 手集計」と違い、各対局者が実際に定跡化している手だけを掘れる。
- **決定性**を担保する。走査は深さ優先で、各ディレクトリの直下エントリだけをソートして
  traversal 順を固定する。並列処理では処理順が保証されないため、出力の決定性は可換な
  加算・min だけで fold/reduce する集計に依存させる。出力は SFEN 昇順・指し手ソートで
  完全に順序づける(同一入力 → 出力 byte 一致)。
- 棋譜は 1 局ずつストリーミング処理し、全棋譜パスや全棋譜本文を一括ロードしない。
  走査中に保持するパスは現在の深さ優先 traversal スタック上のディレクトリエントリだけで、
  ピークメモリは出力サイズ(局面 × 指し手)相当 + **O(最大ディレクトリ幅)**。
  決定的なソート走査にはディレクトリ直下のエントリ一覧の保持が必要なため、この項は
  入力全体でなく「1 ディレクトリ直下のエントリ数」にのみ比例する。floodgate 標準の
  日付分割(`YYYY/MM/DD/`)なら数百エントリで無視できる。全棋譜を単一フラット
  ディレクトリに置く配置は避け、日付等でサブディレクトリに分割して与えること。

## オプション

| フラグ | 既定 | 説明 |
|--------|------|------|
| `--root <dir>` | (必須) | CSA 棋譜のルートディレクトリ。`*.csa` を再帰収集 |
| `--out <file>` | (必須) | 出力 `.db`。常に新規スタンドアロン(既存は上書き) |
| `--min-rating <N>` | `0` | 両対局者の対局時レート下限(0=無効)。CSA 埋め込みの `'black_rate:` / `'white_rate:` を使い、両者が N 以上の棋譜のみ採用。N>0 でレート情報が無い棋譜は除外 |
| `--max-ply <N>` | `32` | この手数までの局面・指し手のみ集計 |
| `--instant-threshold-sec <N>` | `1` | 消費時間による定跡手判定の閾値(秒)。この秒数以下を「即指し」とみなす |
| `--no-instant-filter` | off | 消費時間判定を無効化し、max-ply までの全手を集計する |
| `--winner-only` | off | 勝者側が指した手のみ集計。引き分け・結果不明の棋譜は除外 |
| `--side <both\|black\|white>` | `both` | 集計対象の手番 |
| `--min-count <N>` | `1` | 集計後、採択回数が N 未満の指し手を出力から除外。手が空になった局面は出力しない |

## 消費時間による定跡手判定(既定オン)

手番側ごとに独立して「その側の初手から連続して消費時間 ≤ `--instant-threshold-sec` 秒で
ある間」をその側の定跡内プレフィックスとみなし、**定跡内の手だけ**を集計する。ある側が
一度でも閾値を超えたら(または消費時間が記録されていなければ)、その側は以降すべて集計対象外。
片側が早く長考に入っても、もう一方が即指しを続けている間はその側の手は集計され続ける。

`--no-instant-filter` を付けると判定を無効化し、`--max-ply` までの全手を集計する。

## 集計と出力

- **局面キー**: `rshogi-core` の `Position` で指し手を再生し `to_sfen()` を取る。
  合法性検証を通った手だけを使う。
- **最小 ply 集約**: 同一盤面(ply を除いた盤面 + 手番 + 持ち駒)は最小 ply に集約して
  1 エントリにする(count は ply 違いを合算)。出力の `sfen` 行の手数は最小 ply。
- **指し手行**: `<move> <ponder> 0 0 <count>`。value / depth は常に 0、count は集計値。
- **ponder**: その指し手の直後に相手側が実際に指した手の最頻値。同数タイは USI 文字列の
  辞書順で先のものを採用(決定性)。データが無ければ `none`。
- **出力順**: `sfen` 行は文字列昇順。各局面の指し手は count 降順 → USI 昇順。

## 出力フォーマット例

```
#YANEURAOU-DB2016 1.00
sfen lnsgkgsnl/1r5b1/ppppppppp/9/9/9/PPPPPPPPP/1B5R1/LNSGKGSNL b - 1
7g7f 3c3d 0 0 1234
2g2f 8c8d 0 0 987
...
```

## サマリ出力(stderr)

終了時に総棋譜数・フィルタ別の除外数(パースエラー / 平手でない / レート / winner-only)・
集計に寄与した棋譜数・出力局面数・出力指し手数を stderr に出す。

## 運用ノート

- 本ツールは同一盤面を最小 ply に集約して出力するため、実戦で異なる手数で同一局面に
  合流(transposition)した場合にもヒットさせるには、エンジン側で
  `IgnoreBookPly=true` を設定して使うことを推奨する。
- 既存 `.db` への追記・マージ機能は意図的に持たない(常に新規ファイルを生成する)。
  複数 book の統合が必要な場合は別工程として明示的に行う。
